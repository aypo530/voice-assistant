# Голосовой ассистент задач, напоминаний и встреч (GigaChat)

Пользователь говорит или пишет в свободной форме («Напомни завтра в 10 утра позвонить Ивану») — ассистент понимает запрос,
сохраняет данные и отвечает текстом и голосом. Работает онлайн через **GigaChat (Сбер)**, локально на сервере и полностью
автономно в браузере.

- **Репозиторий:** <ссылка на репозиторий>
- **Работающий прототип:** <ссылка на прототип>

Облако — GigaChat API. Из России он доступен **без VPN**: сервер можно держать в российском облаке (Amvera), и тогда
никаких обходных путей не нужно ни серверу, ни посетителям сайта.

## Что изменилось после переезда с Gemini

| Было (Gemini) | Стало (GigaChat) |
|---|---|
| `GEMINI_API_KEY` (ключ API) | `GIGACHAT_CREDENTIALS` — Authorization key из личного кабинета (Base64 `client_id:client_secret`) |
| ключ действовал бессрочно | **access_token живёт 30 минут**, обновляется автоматически (см. раздел «Токены») |
| два адреса API для ключей `AQ.…` | один адрес `https://api.giga.chat/v1`, авторизация `Bearer` |
| регион мог быть недоступен | работает в РФ без VPN, но требует **сертификаты НУЦ Минцифры** (лежат в `certs/`, в Docker ставятся сами) |
| эмбеддинги 768 | эмбеддинги GigaChat 1024 (`Embeddings`) |
| бесплатный хостинг Render (Франкфурт) | **Amvera** (российское облако, постоянное хранилище `/data`) |

Функциональность, интерфейс, режимы, CSV, офлайн-работа и тесты сохранены полностью — меняется только облачный поставщик.

## Как пользоваться (опубликованный сайт)

Откройте ссылку на прототип — больше ничего не нужно, **VPN не требуется**. Сайт работает на Amvera, ключ GigaChat
хранится в переменных окружения проекта (не в коде), поэтому облачный режим включается сам.
При входе можно вставить собственный ключ GigaChat или нажать «Пропустить» — тогда используется ключ сервера.

Ключ вводится один раз и хранится только в браузере (`localStorage`), на сервер он приходит заголовком `X-LLM-Key`
на каждый запрос и нигде не сохраняется и не логируется.

## Как запустить локально

Нужен Python 3.10+. Windows: двойной щелчок по **`start.bat`**. macOS/Linux: `./start.sh`.
При первом запуске программа сама доустановит библиотеки (2–5 минут) и откроет сайт `http://127.0.0.1:8000`.
Консольное окно не закрывайте — это сервер. Данные лежат в файле `assistant_data.csv` рядом (открывается в Excel).

Ключ GigaChat **необязателен**. Порядок выбора: ключ из окна на сайте → ключ сервера (`GIGACHAT_CREDENTIALS` в `.env`) → локальный режим.

**Про сертификаты на своём компьютере.** GigaChat использует сертификаты НУЦ Минцифры. На Linux/Windows их можно
установить в систему (портал <https://www.gosuslugi.ru/crt>) либо указать путь к корневому сертификату из репозитория:

```bash
GIGACHAT_CA_BUNDLE=certs/russian_trusted_root_ca.crt
```

Приложение само соберёт общий bundle (certifi + сертификат Минцифры). Для быстрой локальной отладки без установки
сертификатов можно поставить `GIGACHAT_TLS_VERIFY=0` — но только локально, не на сервере.

Где взять ключ: <https://developers.sber.ru/studio/workspaces> → проект **GigaChat API** → «Настройки API» →
**Authorization key** (Base64). Можно вместо готового ключа задать `GIGACHAT_CLIENT_ID` и `GIGACHAT_CLIENT_SECRET`.

## Режимы работы

Переключатель вверху страницы: **«Авто»** (GigaChat, при сбое — локально), **«Онлайн»** (только GigaChat, при сбое — сообщение об ошибке),
**«Офлайн»** (GigaChat не используется). Выбор запоминается в браузере.

| | ☁️ Облачный (GigaChat) | 💻 Локальный (на сервере) | 📴 Автономный (в браузере) |
|---|---|---|---|
| Когда | есть ключ и GigaChat доступен | нет ключа, лимит, GigaChat недоступен | нет связи с сервером |
| Речь | GigaChat (аудио прикрепляется к запросу) | faster-whisper | распознавание браузера, если оно локальное, иначе текст |
| Понимание запроса | LLM + строгая JSON-схема | правила для русского (`localnlu.py`) | те же правила в JS (`offline.js`) |
| Поиск по смыслу | эмбеддинги GigaChat | n-граммы + синонимы | n-граммы + синонимы |
| Точность | высокая | ниже: нетипичные формулировки понимает хуже | как в локальном |

Если GigaChat не ответил за 15 секунд (аудио — за 30) или вернул ошибку, запрос тут же выполняется локально,
а следующие минуты облако не опрашивается. Текущий режим показан вверху страницы, ответы локального режима помечены.

## Скорость и качество

- **Одна сетевая операция на голосовой запрос.** Аудио загружается в хранилище GigaChat и прикрепляется к тому же
  запросу, который возвращает JSON с расшифровкой и параметрами (в Gemini это тоже был один вызов). Отдельная
  расшифровка включается только как страховка, если модель не смогла ответить JSON по записи.
- **Токен не тормозит запросы.** Он продлевается в фоне и заранее, а не в момент запроса пользователя.
- **Короткий ответ.** `GIGACHAT_MAX_TOKENS=800` ограничивает генерацию: JSON маленький, ждать дольше нечего.
- **Строгая схема.** `response_format: json_schema` уменьшает число «почти-JSON» ответов, а значит и повторных запросов.
- **Модель можно выбрать под задачу.** `GigaChat-2-Max` (по умолчанию) — лучшее качество разбора и аудио;
  `GigaChat-2-Pro` / `GigaChat-2` — быстрее и дешевле. Запасные модели подставляются автоматически при 429/503/404.
- **Порог семантического поиска** подстраивается переменной `SEARCH_FLOOR_GIGACHAT` (по умолчанию `0.65`) без правки кода.

## Токены GigaChat: как обновляются

GigaChat выдаёт **access_token на 30 минут** (`expires_at` в ответе OAuth). Это не ключ API, а временный токен,
и его нужно продлевать — иначе через полчаса все запросы начнут получать 401. В проекте это закрыто полностью:

1. **Один токен на ключ.** `app/gigachat.py` обменивает Authorization key на токен:
   `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth` с заголовками `Authorization: Basic <ключ>`,
   `RqUID: <uuid4>` и телом `scope=GIGACHAT_API_PERS|B2B|CORP`. Токен кэшируется в памяти процесса.
2. **Обновление заранее.** Если до истечения осталось меньше `GIGACHAT_TOKEN_SKEW_S` (по умолчанию 60 секунд),
   токен запрашивается заново до отправки запроса — пользователь не ждёт OAuth.
3. **Обновление по 401.** Если токен всё же истёк или был отозван, запрос повторяется **один раз** с новым токеном.
4. **Single-flight.** Параллельные запросы на один и тот же ключ ждут одно обновление, а не отправляют десять
   OAuth-запросов (Сбер разрешает не более 10 запросов токена в секунду).
5. **Фоновое продление.** При старте сервера запускается поток, который раз в `GIGACHAT_TOKEN_KEEPALIVE_S` (120 с)
   проверяет срок и продлевает токен. Первый запрос посетителя не платит за OAuth.
6. **Ключи пользователей изолированы.** У каждого ключа (серверного или введённого в браузере) свой токен и своё
   состояние «предохранителя»; ключ пользователя никогда не попадает в логи и на диск.
7. **`expires_at` понимается в секундах и миллисекундах** — разные версии API/прокси отдают по-разному.
   Если время на сервере разошлось с GigaChat, токен считается действующим 30 минут.
8. **Scope подбирается автоматически.** Если ключ относится к B2B/CORP, а не к физлицам, приложение пробует
   `GIGACHAT_API_PERS`, `GIGACHAT_API_CORP`, `GIGACHAT_API_B2B` и запоминает рабочий.
9. **Диагностика.** `GET /api/health` показывает `token_ttl` — сколько секунд осталось токену, и `model` —
   какая модель реально ответила. В логах видно получение и продление токена (без самого токена).

Ничего вручную обновлять не нужно: после перезапуска контейнера токен просто запрашивается заново.

## Автономный режим и сохранность данных

- Если сервер недоступен (нет интернета, сервер «спит» или перезапускается), страница сама переключается на работу прямо в браузере:
  тот же разбор фраз (`app/static/offline.js`, порт `localnlu.py`; совпадение с Python проверяет `python tests/diff_offline.py`),
  записи хранятся на устройстве. Страница открывается без сети благодаря service worker (`app/static/sw.js`) — нужно один раз зайти онлайн.
- Когда связь появляется, изменения сами отправляются на сервер (`POST /api/import`), в чате приходит сообщение.
- Если файл данных потерян (пересборка без постоянного хранилища), на устройстве хранится копия, и при следующем заходе
  записи возвращаются на сервер. Если очистить данные сайта в браузере, копия пропадёт — для надёжности используйте файл (ниже).
- Закрытие или обновление страницы требует подтверждения браузера.

## Файл с записями

- **«скачать CSV»** — один и тот же файл дополняется, а не плодятся копии. На компьютере (Chrome/Edge) файл выбирается один раз и
  дальше дописывается сам. На телефоне и в других браузерах программа просит выбрать прежний файл и скачивает объединённый
  (браузер может назвать его `... (1).csv` — старый удалите). Статус «выполнено» берётся из приложения.
- **«загрузить из файла»** — подгружает записи из файла, скачанного на другом устройстве: новые добавляются, у существующих
  обновляется статус (берётся из файла). Работает и без связи.
- Записи сопоставляются по типу, названию, дате и времени, а не по номеру (номера на разных устройствах разные), дубликаты не создаются.

## Принятые решения

- **LLM только разбирает запрос, действия выполняет код.** Обязательные поля, дубли, прошедшее время и конфликты проверяются
  в коде и покрыты тестами, поэтому все режимы ведут себя одинаково.
- **Речь и смысл — одним запросом к GigaChat.** Аудио загружается в хранилище GigaChat и прикрепляется к тому же запросу,
  который возвращает JSON с расшифровкой и параметрами: одна сетевая операция вместо двух. Если модель не смогла —
  срабатывает отдельная расшифровка, затем локальный Whisper.
- **Строгая JSON-схема ответа** (`response_format: json_schema`, `strict: true`). Если конкретная модель схему не принимает,
  приложение автоматически повторяет запрос обычным JSON-промптом и запоминает это для модели.
- **Автоматический запасной режим:** проверяющему не нужно ничего настраивать, сервис работает даже без ключа и без связи.
- **Озвучка — Web Speech API браузера:** серверный синтез не нужен.
- **Ключ GigaChat** хранится только в переменных окружения хостинга или в браузере пользователя, в репозиторий не попадает;
  токены — только в памяти процесса.
- **CSV вместо БД:** файл виден и открывается в Excel; правка и удаление переписывают его атомарно.

## Публикация на Amvera

В репозитории уже есть `Dockerfile` и `amvera.yml`, отдельная настройка не нужна.

1. **Создайте проект** в <https://cloud.amvera.ru> → «Приложение» → подключите Git-репозиторий (или загрузите код).
2. **Сборка.** Amvera сама найдёт `amvera.yml`: соберёт `Dockerfile`, запустит приложение на порту **8000**
   и примонтирует постоянное хранилище в **`/data`**.
3. **Переменные окружения** (раздел «Переменные» проекта):

   | Переменная | Значение | Обязательно |
   |---|---|---|
   | `GIGACHAT_CREDENTIALS` | Authorization key из личного кабинета (Base64) — **секрет** | да, для облачного режима |
   | `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` (физлицо), `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` | нет, подбирается сам |
   | `TZ_NAME` | `Europe/Moscow` | нет |
   | `MULTI_USER` | `1` — у каждого браузера свои записи | уже задано в Dockerfile |
   | `DATA_FILE` | `/data/assistant_data.csv` | уже задано в Dockerfile |

   `GEMINI_API_KEY` больше не нужен — если он остался, приложение предупредит в логе и проигнорирует его.
4. **Постоянное хранилище.** На тарифе с хранилищем файл `/data/assistant_data.csv` переживает перезапуск и пересборку.
   Без него записи восстановятся из копии в браузере пользователя, но надёжнее включить хранилище.
5. **Домен и HTTPS** Amvera выдаёт автоматически; сертификаты Минцифры уже внутри образа, поэтому GigaChat работает сразу.
6. **Проверка.** Откройте `/api/health`: должно быть `"provider": "gigachat"`, `"cloud": {"state": "ok"}`,
   `"token_ttl"` больше нуля и `"model": "GigaChat-2-Max"`.

Локальная проверка того же образа:

```bash
docker build -t voice-assistant .
docker run --rm -p 8000:8000 -e GIGACHAT_CREDENTIALS=... -v "$PWD/data:/data" voice-assistant
```

Docker Compose не поддерживается Amvera — используется только обычный `Dockerfile`.

## Известные ограничения

- **Уведомлений нет:** напоминание — это запись с датой и временем; ассистент не присылает сигнал в нужный момент (веб-страница не может
  надёжно работать в фоне). Все записи на день можно спросить: «Что у меня сегодня?».
- **Без связи с сервером голос** работает только в браузерах с локальным распознаванием речи (Chrome на Android); везде работает текст.
- **Локальный режим понимает стандартные формулировки**, нетипичные — хуже; с GigaChat точность выше.
- **Один поток на физлицо.** В тарифе `GIGACHAT_API_PERS` у физлица один поток запросов: при нескольких одновременных
  посетителях часть запросов получит 429 и уйдёт в локальный режим. Для публичного сайта лучше B2B/CORP (10 потоков).
- **Тематические ограничения GigaChat.** На часть тем API отвечает `finish_reason: blacklist`; ассистент в этом случае
  обрабатывает запрос локально.
- **Запись голоса — до минуты** (8 МБ), аудио в GigaChat — до 35 МБ.
- **Повтор записи** раскладывается на ограниченный период вперёд, а не на бесконечную серию.
- **CSV вместо БД:** на бесплатном/минимальном тарифе без постоянного хранилища файл теряется при пересборке — записи
  восстанавливаются из копии в браузере, а файл можно скачать и загрузить обратно.
- **Нет интеграции с календарём** (Google Calendar и т.п.).

## Тесты

```bash
cd app
python -m unittest discover -s tests        # 105 тестов, сеть не нужна
```

Проверяются бизнес-логика, локальный разбор фраз, хранилище, поиск, переключение режимов, а также транспорт GigaChat:
получение токена, `expires_at` в секундах и миллисекундах, обновление заранее и по 401, подбор scope, повтор запроса,
JSON-схема и откат к обычному JSON, загрузка/удаление аудио, порядок и батчи эмбеддингов.

## Что улучшил бы при наличии времени

Интеграцию с реальным календарём, базу данных вместо CSV, уведомления в нужное время (Web Push), бесконечные повторы с правилами,
голосовое переименование записи, потоковые ответы GigaChat для мгновенного первого токена, калибровку порогов семантического поиска,
распознавание речи в браузере без сервера (Whisper в WebAssembly).
