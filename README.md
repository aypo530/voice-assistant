# Голосовой ассистент задач, напоминаний и встреч

Пользователь говорит или пишет в свободной форме («Напомни завтра в 10 утра позвонить Ивану») — ассистент понимает запрос,
сохраняет данные и отвечает текстом и голосом. Облачный режим работает на **GigaChat (Сбер)**, есть локальный режим на сервере
и полностью автономный режим в браузере.

- **Репозиторий:** (https://github.com/aypo530/voice-assistant)
- **Работающий прототип:** (https://voice-assistant-aypo500.msk1.amvera.tech/)

## Как пользоваться (опубликованный сайт)

Откройте ссылку на прототип — больше ничего не нужно, **VPN не требуется**: сайт работает на российском хостинге Amvera,
а запросы идут в GigaChat, который доступен из России напрямую. Ключ Сбера хранится в переменных окружения проекта на хостинге
(не в коде), поэтому облачный режим включается сам.
При входе можно вставить собственный ключ GigaChat или нажать «Пропустить» — тогда используется ключ сервера.

## Как запустить локально

Нужен Python 3.10+. Windows: двойной щелчок по **`start.bat`**. macOS/Linux: `./start.sh`.
При первом запуске программа сама доустановит библиотеки (2–5 минут) и откроет сайт `http://127.0.0.1:8000`.
Консольное окно не закрывайте — это сервер. Данные лежат в файле `assistant_data.csv` рядом (открывается в Excel).

Ключ GigaChat **необязателен**. Порядок выбора: ключ из окна на сайте → ключ сервера (`GIGACHAT_AUTH_KEY` в `.env`) → локальный режим.
Свой ключ удобно положить в `.env` (образец — `app/.env.example`):

```
GIGACHAT_AUTH_KEY=MDE4...ваш ключ авторизации...
```

## Ключ GigaChat и обновление токенов

### Где взять ключ в случае локального запуска

1. Зайдите в [личный кабинет GigaChat API](https://developers.sber.ru/studio/workspaces/my-space/get/gigachat-api) (нужен аккаунт Сбер ID).
2. Создайте проект (для физлиц — бесплатный freemium-тариф).
3. На странице **«Настройка API»** нажмите **«Получить ключ»** — это и есть **Authorization key**: длинная строка Base64.
   Рядом показаны **Client ID** и **Scope** (`GIGACHAT_API_PERS` для физлиц) — они нужны только для справки:
   ассистенту достаточно ключа авторизации, Client ID и Client Secret отдельно вводить не надо.
4. Вставьте строку в окно «🔑 Ключ» на сайте (она останется в браузере) или в переменную `GIGACHAT_AUTH_KEY` на хостинге.

Кнопка «Проверить ключ» реально ходит в GigaChat: в ответе видно либо «Ключ принят», либо причину отказа
(например, вставлен Client ID вместо ключа авторизации).

### Почему токены нужно обновлять

Ключ авторизации — это не токен. По нему приложение получает **access token**:

```
POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth
Authorization: Basic <ключ авторизации>
RqUID: <uuid4>
Content-Type: application/x-www-form-urlencoded

scope=GIGACHAT_API_PERS
→ {"access_token": "eyJhbGci...", "expires_at": 1679471442}
```

Такой токен живёт **30 минут** — это требование Сбера (в условиях использования API), поэтому обновлять его обязательно,
иначе через полчаса запросы начнут возвращать `401`.

Как это реализовано в проекте (`app/llm.py`):

- **Кеш на каждый ключ.** Токен хранится в памяти процесса вместе с `expires_at`; повторно за ним не ходим.
  Ключ сервера и ключи пользователей (заголовок `X-GigaChat-Key`) кешируются раздельно — чужой ключ не «затирает» состояние.
- **Обновление заранее.** За `GIGACHAT_TOKEN_REFRESH_S` (по умолчанию 300 с, то есть за 5 минут до истечения) токен
  запрашивается заново — в фоне, отдельным потоком, поэтому запрос пользователя никогда не ждёт сервер авторизации.
- **Один запрос на всех.** Запрос токена защищён блокировкой: при одновременных репликах в Сбер уйдёт один запрос,
  а не десять (у сервиса ограничение — 10 запросов токена в секунду).
- **Повтор при 401.** Если Сбер всё же ответил `401` (токен отозван, часы разъехались, проект пересоздан), токен
  выбрасывается, запрашивается новый, и запрос **автоматически повторяется один раз** — пользователь этого не замечает.
- **Единицы `expires_at`.** Поддерживаются и секунды, и миллисекунды (разные версии API отдают разное).
- **На диск токен не попадает.** Только память процесса; в логи пишется лишь короткий хеш ключа, сам ключ и токен не логируются.
- **Если ключ неверный**, ассистент не «падает»: он на 15 минут переходит в локальный режим и пишет об этом в интерфейсе.

Диагностика: `GET /api/health` возвращает `cloud` (состояние облака) и `token_left` — сколько секунд осталось у текущего токена.

### Сертификаты Минцифры (TLS)

`api.giga.chat` и сервер авторизации используют сертификаты **НУЦ Минцифры**, которых нет в стандартном наборе Python.
Без них `requests` падает с `SSL: unable to get local issuer certificate` — это самая частая причина «GigaChat недоступен» на новом хостинге.
Поэтому корневой сертификат лежит в репозитории — `app/certs/russian_trusted_root_ca_pem.crt` — и автоматически склеивается
со стандартным набором `certifi` (файл `models/gigachat_ca_bundle.pem` создаётся при первом запросе). В Docker-образе
дополнительно установлен пакет `ca-certificates`.

Если в вашей сети нужен свой бандл — задайте `GIGACHAT_CA_BUNDLE=/путь/к/bundle.pem`.
Отключить проверку TLS можно через `GIGACHAT_VERIFY_SSL=0`, но только для отладки.

### Модели

| Назначение | Переменная | По умолчанию | Комментарий |
|---|---|---|---|
| Понимание запроса | `GIGACHAT_MODEL` | `GigaChat-2` | при недоступности автоматически пробуются `GIGACHAT_FALLBACK_MODELS` |
| Запасные модели | `GIGACHAT_FALLBACK_MODELS` | `GigaChat-2-Pro,GigaChat-2-Lite,GigaChat-2-Max,GigaChat` | перебор идёт по списку, рабочая модель запоминается |
| Распознавание речи | `GIGACHAT_AUDIO_MODEL` | `GigaChat-2-Max` | умеет анализировать аудиофайлы |
| Поиск по смыслу | `GIGACHAT_EMBED_MODEL` | `Embeddings` | можно `Embeddings-2` или `EmbeddingsGigaR` |

Хотите максимум качества разбора — поставьте `GIGACHAT_MODEL=GigaChat-2-Max` (или `GigaChat-3-Ultra`).
Хотите минимальную задержку — `GigaChat-2-Lite`. Ничего не сломается в любом случае: неподходящая модель
пропускается, и берётся следующая доступная (вплоть до автоматического `GET /models`, если модель переименовали).

Модель понимает русский «из коробки», поэтому промпт остался прежним: ассистент по-прежнему просит
строгий JSON (`response_format: json_schema`), а если конкретная модель схему не принимает — переходит на JSON в промпте.

## Режимы работы

Переключатель вверху страницы: **«Авто»** (GigaChat, при сбое — локально), **«Онлайн»** (только GigaChat,
при сбое — сообщение об ошибке), **«Офлайн»** (GigaChat не используется). Выбор запоминается в браузере.

| | ☁️ Облачный (GigaChat) | 💻 Локальный (на сервере) | 📴 Автономный (в браузере) |
|---|---|---|---|
| Когда | есть ключ и GigaChat доступен | нет ключа, лимит, GigaChat недоступен | нет связи с сервером |
| Речь | GigaChat (аудио вложением в модель) | faster-whisper | распознавание браузера, если оно локальное, иначе текст |
| Понимание запроса | LLM | правила для русского (`localnlu.py`) | те же правила в JS (`offline.js`) |
| Поиск по смыслу | эмбеддинги GigaChat | n-граммы + синонимы | n-граммы + синонимы |
| Точность | высокая | ниже: нетипичные формулировки понимает хуже | как в локальном |

Если GigaChat не ответил за `CLOUD_TIMEOUT_S` (по умолчанию 20 с) или вернул ошибку, запрос тут же выполняется локально,
а следующие минуты облако не опрашивается (свой «предохранитель» на каждый ключ). Текущий режим показан вверху страницы,
ответы локального режима помечены.

Если конкретная модель не умеет работать с аудио, речь распознаётся локальным faster-whisper, а **понимание запроса всё равно
остаётся в GigaChat** — точность разбора не падает, добавляется только время на распознавание.

## Автономный режим и сохранность данных

- Если сервер недоступен (нет интернета, сервер «спит» или перезапускается), страница сама переключается на работу прямо в браузере:
  тот же разбор фраз (`app/static/offline.js`, порт `localnlu.py`; совпадение с Python проверяет `python tests/diff_offline.py`),
  записи хранятся на устройстве. Страница открывается без сети благодаря service worker (`app/static/sw.js`) — нужно один раз зайти онлайн.
- Когда связь появляется, изменения сами отправляются на сервер (`POST /api/import`), в чате приходит сообщение.
- На хостинге с постоянным хранилищем (Amvera, папка `/data`) записи не теряются при перезапуске. Если хранилище не подключено,
  на устройстве остаётся копия, и при следующем заходе записи возвращаются на сервер. Если очистить данные сайта в браузере,
  копия пропадёт — для надёжности используйте файл (ниже).
- Закрытие или обновление страницы требует подтверждения браузера.

## Файл с записями

- **«скачать CSV»** — один и тот же файл дополняется, а не плодятся копии. На компьютере (Chrome/Edge) файл выбирается один раз и
  дальше дописывается сам. На телефоне и в других браузерах программа просит выбрать прежний файл и скачивает объединённый
  (браузер может назвать его `... (1).csv` — старый удалите). Статус «выполнено» берётся из приложения.
- **«загрузить из файла»** — подгружает записи из файла, скачанного на другом устройстве: новые добавляются, у существующих
  обновляется статус (берётся из файла). Работает и без связи.
- Записи сопоставляются по типу, названию, дате и времени, а не по номеру (номера на разных устройствах разные), дубликаты не создаются.

## Архитектура

```
Браузер  app/static/index.html (чат, список, подсказки), offline.js (автономный движок), sw.js (кэш страницы)
   │  /api/voice · /api/message · /api/items · /api/search · /api/import · /api/export.csv · /api/key/check
app/server.py       HTTP-слой (FastAPI), без логики; ключ и режим запроса приходят в заголовках X-GigaChat-Key / X-Mode
app/assistant.py    бизнес-логика: проверки, уточнения, дубли, конфликты, выбор режима, ответы
   ├── app/llm.py          GigaChat: токен доступа (кеш + автообновление), JSON-разбор запроса, аудио вложением,
   │                       эмбеддинги, перебор моделей, «предохранитель» при сбоях
   ├── app/certs/          корневой сертификат Минцифры (TLS для api.giga.chat)
   ├── app/stt_local.py    faster-whisper (запасное распознавание речи)
   ├── app/localnlu.py     правила разбора русских фраз (замена LLM)
   ├── app/search.py       поиск: слова → эмбеддинги GigaChat → n-граммы + синонимы
   ├── app/storage.py      CSV: чтение, запись, правка, удаление
   └── app/textutil.py     даты, русские формулировки
app/tests/                 83 теста без сети (python -m unittest discover -s tests, из папки app),
                           в том числе жизненный цикл токена (кеш, обновление, повтор при 401)
                           diff_offline.py — сравнение браузерного движка с Python на случайных фразах
```

## Принятые решения

- **LLM только разбирает запрос, действия выполняет код.** Обязательные поля, дубли, прошедшее время и конфликты проверяются
  в коде и покрыты тестами, поэтому все режимы ведут себя одинаково.
- **Речь и смысл — одним запросом.** Аудио загружается в хранилище GigaChat и передаётся модели вложением: модель сама
  расшифровывает речь и возвращает JSON. Это сохраняет прежнюю задержку (один сетевой раунд на реплику) и убирает
  рассинхрон «распознал одно — понял другое».
- **Токен обновляется сам.** 30 минут — срок жизни токена у Сбера, поэтому кеш + обновление за 5 минут + повтор при 401.
  Пользователю не нужно ничего перезапускать.
- **Автоматический запасной режим:** проверяющему не нужно ничего настраивать, сервис работает даже без ключа и без связи.
- **Озвучка — Web Speech API браузера:** серверный синтез не нужен (и не тратит токены).
- **Ключ GigaChat** хранится только в переменных окружения хостинга или в браузере пользователя, в репозиторий не попадает;
  в логи не пишется.
- **CSV вместо БД:** файл виден и открывается в Excel; правка и удаление переписывают его атомарно.

Особенности Amvera, о которых стоит знать:

- **VPN не нужен** ни посетителям, ни серверу: и хостинг, и GigaChat находятся в России.
- Контейнер засыпает при простое на дешёвых тарифах — первый запрос после паузы чуть медленнее, страница в это время
  работает автономно и сама синхронизируется.
- **Память.** `PRELOAD_LOCAL=0` (уже стоит в Dockerfile) — локальные модели не грузятся при старте, память тратится
  только когда они реально понадобятся. Если локальное распознавание речи не нужно совсем, уберите `faster-whisper`
  из `Dockerfile` — облачный путь всё равно обработает аудио.
- Логи смотрите в панели Amvera: там видно получение нового токена (`GigaChat: получен новый токен`) и причины
  перехода в локальный режим.

Локальная проверка того же образа:

```
docker build -t voice-assistant .
docker run -p 8000:8000 -e GIGACHAT_AUTH_KEY=<ключ> -v $(pwd)/data:/data voice-assistant
```

Тесты не ходят в интернет: `GIGACHAT_AUTH_KEY` в них пустой, а сетевые вызовы подменяются. Отдельный блок
`TokenLifecycle` проверяет именно то, что легко сломать при переезде: кеш токена, обновление за 5 минут до истечения,
раздельные токены для разных ключей, повтор запроса после `401` и переход на другую модель, если первая недоступна.

## Известные ограничения

- **Уведомлений нет:** напоминание — это запись с датой и временем; ассистент не присылает сигнал в нужный момент (веб-страница не может
  надёжно работать в фоне). Все записи на день можно спросить: «Что у меня сегодня?».
- **Лимиты GigaChat.** На бесплатном (freemium) тарифе есть ограничения по числу запросов и токенов; при их исчерпании
  ассистент на время переходит в локальный режим — это видно в интерфейсе, ничего не ломается.
- **Без связи с сервером голос** работает только в браузерах с локальным распознаванием речи (Chrome на Android); везде работает текст.
- **Локальный режим понимает стандартные формулировки**, нетипичные — хуже; с GigaChat точность выше.
- **Повтор записи** раскладывается на ограниченный период вперёд, а не на бесконечную серию.
- **Нет интеграции с календарём** (Google Calendar и т.п.).

## Что улучшил бы при наличии времени

Интеграцию с реальным календарём, базу данных вместо CSV, уведомления в нужное время (Web Push), бесконечные повторы с правилами,
голосовое переименование записи, озвучку через SaluteSpeech (сейчас — Web Speech API браузера), калибровку порогов
семантического поиска под `EmbeddingsGigaR`, распознавание речи в браузере без сервера (Whisper в WebAssembly).
