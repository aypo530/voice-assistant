# Голосовой помощник: задачи, напоминания, встречи

Прототип голосового ассистента для управления личными делами. Пользователь говорит или пишет в свободной форме,
ассистент понимает запрос, выполняет действие и отвечает текстом и голосом.

**Работает без VPN** — развёрнут в российском облаке Amvera, в качестве нейросети используется GigaChat.

## Что умеет

| Сценарий | Пример |
|---|---|
| Создать задачу / напоминание | «Напомни мне завтра в 10 утра позвонить Ивану», «В пятницу нужно отправить отчёт» |
| Создать встречу | «Добавь встречу с командой завтра в 15:00», «В четверг в 11 у меня встреча с дизайнером» |
| Список за период | «Что у меня сегодня?», «Какие задачи на завтра?», «Что запланировано на эту неделю?» |
| Поиск старых записей | «Найди задачу про презентацию», «Когда у меня была встреча с Иваном?», «Я когда-то ставил задачу по договору» |
| Уточнение | «Поставь встречу с Иваном завтра» → «На какое время поставить встречу?» → «в 15» |

Относительные даты: сегодня, завтра, послезавтра, в пятницу, через два часа, на следующей неделе, до конца недели, 5 ноября.

**Дополнительно (из списка «плюсов»):** отметка выполненным, удаление и перенос голосом («Перенеси встречу с дизайнером на пятницу»),
контекст диалога («перенеси её на завтра»), предупреждение о конфликте встреч, семантический поиск, несколько пользователей
(у каждого браузера своя изолированная база), экспорт в CSV.

## Архитектура

```
Браузер (Web Speech API: распознавание и озвучка речи)
   │  JSON: текст + локальное время клиента
   ▼
app.py ─ Flask, тонкий HTTP-слой
   ▼
assistant/service.py ─ бизнес-логика: сценарии, уточняющие вопросы, формирование ответов
   ├─ assistant/llm.py     GigaChat: разбор команды в JSON, семантический поиск; токен обновляется сам
   ├─ assistant/nlu.py     запасной разбор правилами (работает без нейросети)
   ├─ assistant/dates.py   русские даты и время (детерминированно)
   ├─ assistant/search.py  нечёткий поиск: основы слов, синонимы, опечатки
   └─ assistant/store.py   SQLite
```

Ключевые решения:

1. **Смысл — у нейросети, даты — у кода.** GigaChat определяет намерение, тип и название. Даты и время всегда считает `dates.py`:
   модель не ошибётся в «в пятницу» и не выдумает дату.
2. **Ответы формирует код, а не модель.** Ассистент не может «придумать» несуществующую запись.
3. **Устойчивость.** Если GigaChat недоступен (сеть, лимиты, таймаут), запрос обрабатывается правилами. Приложение продолжает работать,
   в интерфейсе виден режим («GigaChat» / «базовый режим»). После сбоя модель не опрашивается 30 секунд, чтобы не тормозить ответы.
4. **Хранение — SQLite**, один файл: тип, название, дата, время, статус, дата создания, владелец.
5. **Время берётся у клиента**, поэтому «сегодня» и «через два часа» верны в любом часовом поясе.
6. **Без внешних ресурсов во фронтенде** (шрифты, CDN): страница не зависит от блокировок.

## Запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env        # вставьте GIGACHAT_AUTH_KEY (без него работает базовый режим)
python app.py               # http://localhost:8080
python -m unittest discover -s tests -v   # тесты (ключ и сеть не нужны)
```

Голосовой ввод работает в Chrome, Edge, Safari (нужен HTTPS или localhost). В других браузерах доступен текстовый ввод.

Docker: `docker build -t assistant . && docker run -p 8080:8080 -e GIGACHAT_AUTH_KEY=... -v $(pwd)/data:/data assistant`

## Деплой на Amvera

1. Создать проект на cloud.amvera.ru (тип «Приложение», Python, pip).
2. В «Переменных» проекта добавить секрет `GIGACHAT_AUTH_KEY`.
3. `git remote add amvera https://git.amvera.ru/<логин>/<проект>` и `git push amvera master`.
4. Включить публичный домен в настройках проекта.

Файл `amvera.yml` уже в репозитории. База хранится в `/data` и сохраняется между обновлениями.

## Получение ключа GigaChat

developers.sber.ru → Studio → «Мой GigaChat API» → «Настройка API» → «Получить ключ». Ключ показывается один раз.
Scope: `GIGACHAT_API_PERS` (бесплатный Freemium). Access token живёт 30 минут, `llm.py` обновляет его автоматически.
